=====
V4010
=====

.. problem-summary:: V4010

Online change refused a schema edit because the state migration planner
cannot justify carrying the running values into the candidate. The candidate
and the running application both carry stable variable IDs, but at least one
ID that exists on both sides is bound to an entry the planner cannot migrate:
a changed variable type outside the conversion policy, a changed array
descriptor, a current string value that no longer fits the candidate's
maximum length, a changed function-block tail layout, or a migration decision
that names nothing or asks to preserve a size-mismatched pair.

For an out-of-policy type change the refusal is decidable per entity: the
response carries a ``pairs`` array with every offending entity — its stable
ID, debug name, the two storage classes, and whether their sizes match — and
the client resubmits the identical container with a ``migration`` map keyed
by UID. ``"init"`` discards the old value and lets the candidate's initial
value stand (the fail-closed default); ``"preserve"`` keeps the old storage
bytes and reinterprets them under the candidate type, is legal only when
``sizeEqual`` is true, and means the value may no longer be valid.

Example
-------

A session stages a candidate that retypes a persistent variable ``Counter``
from ``I32`` to ``U32`` while keeping its stable ID. The planner reports the
pair and stages nothing:

.. code-block::

   {"command":"acceptEdits","program":[...]}
   {"response":"error","vCode":"V4010","message":"candidate state cannot be migrated: type changes are outside the migration policy: entity 7 (Counter) I32 -> U32","pairs":[{"uid":7,"name":"Counter","from":"I32","to":"U32","sizeEqual":true}]}

The client decides per variable and resubmits the identical container:

.. code-block::

   {"command":"acceptEdits","program":[...],"migration":{"7":"preserve"}}

Without decisions, keep the edit inside what the planner can justify: renames,
reorders, and adding or removing variables migrate; a structural change (a
string maximum that shrinks below the current value, a changed array
descriptor, or an FB field layout change) does not. Split the edit so the
incompatible declaration changes are applied as a cold start, or adjust the
candidate so every shared ID keeps its entry. See :doc:`V4007` when the
candidate lacks the stable IDs a migration needs.
