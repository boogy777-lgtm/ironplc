=====
V4008
=====

.. problem-summary:: V4008

Online change refused the candidate because its task schedule differs from
the running application's. The task table — task priorities, task types,
intervals, watchdogs, and the program instance bindings — is identity, not
state: the runtime validates it field by field at stage time and treats any
difference as a schedule change, which is a cold start in the P0 protocol.

Example
-------

The candidate was compiled from a program whose configuration assigns a
different priority to the cyclic task. The host answers the staged edit with
V4008 and the original schedule keeps running:

.. code-block::

   {"command":"acceptEdits","program":[...]}
   {"response":"error","vCode":"V4008","message":"candidate task schedule is incompatible with the active application"}

To change the schedule on purpose, accept the candidate in ``replace`` mode:
``{"command":"acceptEdits","program":[...],"mode":"replace"}``. A replace does not
compare the task schedule; the new application starts from its initial values and
only its ``PERSISTENT`` variables with an equal declaration keep their value (see
:ref:`ironplcvm-replace`).

To fix this error, keep the candidate's task configuration identical to the
running application's — priorities, task types, intervals, and watchdog
times must all match — and change only program logic. When the schedule
itself must change, send the candidate in ``replace`` mode; a tested schedule
change cannot be untested back because task identity is not part of the
carried-over state.
